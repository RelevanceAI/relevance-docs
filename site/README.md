# Relevance AI docs — Fumadocs site

The docs site that replaces Mintlify. Next.js + Fumadocs, exported to static
files, served at `/docs`.

```bash
cd site
npm install
npm run build          # -> site/out, a plain static directory
npx serve out          # or any static host
```

## Verification gates

Three checks guard the migration. All three must pass before cutover.

```bash
node tools/check-tracked.mjs   # everything needed to build is committed
node tools/check-redirects.mjs # host configs are valid for Vercel + CF
node tools/check-seo.mjs       # canonical/title/og/JSON-LD on every page
node tools/check-parity.mjs   # every indexed URL still exists
node tools/check-nav.mjs      # every docs.json page is in the sidebar
node tools/check-links.mjs    # no broken internal links
node tools/check-icons.mjs <fontawesome-all.min.css>
node tools/check-dist.mjs     # serves dist/ strictly and fails on any 404
```

## How the content migrates unedited

The `.mdx` files were moved into `content/docs/` with `git mv` and otherwise
left alone. No import lines were added and no components were rewritten.
Four things make that work:

1. **`components/mdx.tsx`** registers every Mintlify component globally, so
   `<Accordion>`, `<Card>`, `<Note>` and the rest resolve with no imports.
2. **`lib/remark-snippet.mjs`** rewrites `<Snippet file="x.mdx" />` into
   Fumadocs' native `<include>`, so snippets ride the framework's own include
   pipeline rather than a hand-maintained import map.
3. **`lib/remark-heading-components.mjs`** injects a module-scope import for
   components used *inside headings*. Fumadocs extracts headings for the table
   of contents outside the component provider, so `### Foo <Badge>Beta</Badge>`
   otherwise hard-fails the build with `Badge is not defined`.
4. **`lib/remark-base-path.mjs`** applies the `/docs` basePath to
   root-relative links and raw asset attributes.

## Things that bit, and why they are worth knowing

**Internal links (1,547 of them).** `CLAUDE.md` tells authors to write
`/get-started/support`, which Mintlify resolves against its own docs root.
Under `basePath: '/docs'` nothing in Next or Fumadocs rewrites them — the
first full build had **124 distinct broken targets**. `remark-base-path`
fixes them; `check-links.mjs` stops them coming back.

**Images are two different problems.** Markdown images (`![](/images/x.png)`,
411 of them) are converted by fumadocs-mdx into static imports resolved from
`public/`, and basePath is applied automatically — prefixing them too makes
the build look for `public/docs/images/...` and fail. Raw `src="/images/..."`
attributes (82) get no such treatment and *must* be prefixed. The plugin
therefore skips markdown images and handles only attributes.

**Font Awesome Pro.** Mintlify bundles FA Pro. The corpus uses 305 icon
names; 41 of them (81 usages) are Pro-only and render as blank squares on FA
Free — `messages` alone appears 11 times. `PRO_TO_FREE` in
`components/mintlify/index.tsx` maps all 41 to Free equivalents. Buying an FA
Pro licence would let that table be deleted; `brand-android`, `notion` and
`typewriter` are the only three with no close Free match.

**The manifest was never committed.** The repo's root `.gitignore` carried
bare `package.json` and `package-lock.json` patterns, and git matches those at
ANY depth — so `site/package.json` was silently skipped by `git add -A`. Every
local build worked, because the file exists on disk. Vercel cloned the repo,
found no manifest, **skipped the install step entirely**, and died in 12
seconds with `next: command not found`. The patterns are now scoped to the
repo root (`/package.json`), and `tools/check-tracked.mjs` asserts that every
file needed to build is committed — which is the only place this class of bug
is visible, since building cannot reveal it.

Related: the build command is `npm run build`, not a bare `next build`. npm
puts `node_modules/.bin` on PATH; a plain shell does not.

**Verify from a clean clone, not the working tree.** The single check that
would have caught both of the above:

```bash
git clone <repo> /tmp/verify && cd /tmp/verify/site
npm install && npm run build:deploy
```

**The two hosts want different wildcard syntax.** `docs.json` mixes two
forms: `:slug*` and a bare `*`. Cloudflare wants `*` + `:splat`; Vercel wants
a named `:path*` and rejects a bare `*`. The generator originally normalised
only the Cloudflare side, so three rules shipped to `vercel.json` with a bare
`*` — and Vercel validates routes at deployment-CREATION time, so it threw out
the **entire deployment** before any build ran. 3 bad rules took the other 160
with them, and there was no build log to inspect; the error only surfaced as a
bot comment on the PR. `tools/check-redirects.mjs` now validates both configs
against each platform's actual syntax and limits.

**Shiki is stricter than Mintlify.** Fence languages `Python` (6), `python3`
(4), `https` (2) and `SOQL` (1) are not Shiki languages and threw
`Language not found`, failing the whole build. `lib/remark-code-lang.mjs`
lower-cases, applies aliases, and falls back to `text` so a bad fence
degrades instead of breaking CI.

**Folder-index collisions.** `guides.mdx` sat beside `guides/`, and
`changelog.mdx` beside `changelog/`. Fumadocs wants a folder's own page at
`<folder>/index.mdx`; both were moved there. The URLs are unchanged.

**Three empty files.** `build/agents/extend-your-agent/api.mdx`,
`build/workforces/workforce-overview/tips-and-tricks.mdx` and
`integrations/api-integration/relevanceai-api-keys.mdx` were 0 bytes. Mintlify
served them as blank 200s; a real schema rejects them. All three were
orphaned with zero inbound links, so they were deleted — **the only three URLs
that change behaviour** (blank 200 to 404). Restore them as stubs if you'd
rather keep the URLs.

## Theming

`app/relevance.css` holds the whole theme, built from tokens measured off
relevanceai.com: Sora for headings at weight 400 with tight negative
tracking, Inter for body and UI, `#6056FF` primary, `#0D162F` ink, hairline
`#E6E7EA` rules, 8px radii. It also maps Fumadocs' own `--color-fd-*`
variables onto those tokens so the chrome matches the content. Dark mode is
a token override in the same file.

## Generated files

`tools/gen-nav.mjs` and `tools/gen-redirects.mjs` read `docs.json` and write
`content/docs/**/meta.json`, `public/_redirects` and `vercel.json`. Re-run
them after editing `docs.json`:

```bash
node tools/gen-nav.mjs
node tools/gen-redirects.mjs
```

`docs.json` is kept as the navigation source of truth for now. Once Mintlify
is switched off it can either stay as the input to these generators or be
retired in favour of editing `meta.json` directly.

## Deployment

`npm run build` writes `site/out`; `node tools/pack-dist.mjs` gathers it into
`site/dist`, which is the **deployable output root**. Everything sits under
`dist/docs/`, so the output root is served at the DOMAIN root and every public
URL is `/docs/...` natively — which is what host redirect rules expect, since
`_redirects` and `vercel.json` paths are written from the domain root.

The split exists because Next's static export puts pages under `out/docs/`
while `_next`, `public/` and the route handlers land at `out/` root, even
though every URL in the HTML is prefixed with `/docs`.

### Vercel

`vercel.json` is generated with the full project config — `framework: null`
(this is a packed static export, not an app for Vercel to build itself),
build command, output directory, the 163 redirects, cache headers and
`cleanUrls`.

`cleanUrls: true` is load-bearing. Vercel defaults it to **false**, and a
plain static output is then served only at `.html` paths:
`/docs/get-started/introduction` 404s while
`/docs/get-started/introduction.html` renders. Cloudflare Pages strips the
extension implicitly, which is why the omission was invisible until the site
was actually on Vercel. With it on, `/x.html` also 308s to `/x`, so the
`.html` forms cannot be indexed as duplicates of the canonical URLs.

Project settings that are **not** in the file and must be set in the Vercel
UI once:

| Setting | Value |
|---|---|
| Root Directory | `site` |
| Framework Preset | Other |

Then point the marketing site's existing `/docs` rewrite at this deployment.
`relevanceai.com` is already on Vercel and already rewrites `/docs` — today
into Mintlify's multi-tenant app (`x-matched-path: /_sites/[subdomain]/...`),
so this is a repoint, not a new integration.

### Cloudflare Pages

Build output directory `site/dist`; `_redirects` and `_headers` are generated
at the output root and picked up automatically. Note that because `/docs` is a
path on the Vercel-hosted apex domain, traffic still transits Vercel either
way, so Cloudflare's unmetered egress does not actually apply here.

The config uses **`assetPrefix`, not `basePath`**, and that distinction is
load-bearing. `basePath` rewrites `next/link` at runtime but leaves the plain
`<a>` elements that MDX produces alone, so no setting is right for both:
prefixing MDX links in the remark plugin produced `/docs/docs/...` on every
in-page link, and not prefixing them left server-rendered hrefs that 404 for
crawlers and with JavaScript disabled. Making `/docs` a real route segment
and pointing `assetPrefix` at it prefixes everything exactly once.

`tools/check-dist.mjs` guards this: it serves `dist/` the way a host would,
with no path guessing, applies the generated redirect rules, and fails on any
404 or broken image.

## SEO parity

Head tags were compared page-by-page against what Mintlify serves today, and
the first build was missing five things that matter for search:

| | Mintlify | First build | Now |
|---|---|---|---|
| `canonical` | yes | **missing** | yes |
| `<title>` | `Page - Relevance AI Documentation` | `Page` | matches |
| `og:url` / `og:site_name` | yes | **missing** | yes |
| JSON-LD (Organization + WebSite) | yes | **missing** | yes |
| Sitemap scope | 289 URLs | **385** | 289 |

The sitemap one was the subtle one: the build produces 385 pages, but 96 are
orphans that Mintlify serves without advertising. Listing them would have
pushed 96 previously-unindexed pages — including the leftover Mintlify
starter-kit API stubs — into the index at cutover. They stay reachable and
unlisted, exactly as now.

`robots.txt` mirrors Mintlify's, including its `Content-Signal` AI-usage
declaration; changing that is a policy decision, not a migration detail.

Two pages Mintlify omits from its own sitemap, `/docs/community` and
`/docs/changelog`, are omitted here too for exact parity. Both are linked
from every page so they remain crawlable. `INCLUDE_GLOBAL_ANCHORS` in
`app/sitemap.ts` flips that on — a small opportunity, not a regression.

bubble is documented in CLAUDE.md but used on zero pages.

  whichever host is chosen.

  Mintlify-era files and are not wired into this app. The Invent callout is
