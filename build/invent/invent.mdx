## What is Invent

Invent is a forward deployed agent built into Relevance AI. Give it a business process and it works with you to understand how that process runs, including the systems involved and the decisions that require judgment.

It then creates and coordinates the Agents, Tools, Triggers, and Workforces needed to carry out the process, with performance requirements in place before real work begins.

Its job continues after launch. Invent monitors live performance, detects quality problems, proposes and tests improvements, and measures the results in the systems where the work lands. You bring the process knowledge; Invent builds and manages the Agent team underneath it.

## What can Invent do?

<CardGroup cols={2}>
  <Card title="Understand your process" icon="magnifying-glass">
    Invent works through your process with you, including its inputs, systems, judgment calls, exceptions, and definition of success. It can read the process back to you, identify missing information, and help determine which parts should become Tools, Agents, or Workforces.
  </Card>
  <Card title="Build and connect the Agent team" icon="diagram-project">
    Invent creates the Agents needed for the process, equips them with the required Tools and context, connects the systems where the work happens, and wires the Triggers and Workforces that coordinate the process from end to end.
  </Card>
  <Card title="Set and maintain the quality bar" icon="gauge">
    Invent defines the checks each Agent must pass before launch and samples live runs after deployment. When quality drops, it diagnoses the problem and proposes changes to prompts, Tools, examples, models, or orchestration. It can test those changes against the same requirements before you approve them.
  </Card>
  <Card title="Measure results and find the next opportunity" icon="chart-line">
    Invent reads outcomes from the systems where the work lands, not only from Agent logs, so it can connect Agent activity to measures such as response time, qualified leads, meetings booked, or cases resolved. It can also identify recurring manual work and recommend additional Agents worth building.
  </Card>
</CardGroup>

## Access controls

### Availability

Invent is available to organization admins by default. An organization admin can turn on Invent for everyone in an individual project from that project's settings.

### Enterprise security controls

<AccordionGroup>
  <Accordion title="Project isolation">
    Invent's access to Relevance AI is scoped to the active project at the API-key and fine-grained authorization layers, not only in the interface. Each internal platform request uses the active project ID and the caller's API key, then passes through the standard authorization checks. Enabling Invent in a sandbox project does not grant it access to assets in a production project.
  </Accordion>

  <Accordion title="Integration reach">
    Within the active project, Invent can use connected integrations such as Salesforce or Gmail with credentials available to that project. The project is the access boundary, so connect only sandbox credentials if the project must remain isolated from production data.
  </Accordion>

  <Accordion title="Data egress">
    Conversation content is sent to the selected LLM provider to generate responses. Web search is off by default and used only when enabled for a message. Voice is feature-gated and off by default. Memory is off unless the user enables it. Audit data and operational metrics stay within Relevance AI unless the organization has configured enterprise event streaming to a customer-controlled destination.
  </Accordion>
</AccordionGroup>

## Invent features

<Tabs>
  <Tab title="Set up and use Invent">
    <AccordionGroup>
  <Accordion title="Start a task" icon="wand-magic-sparkles">
    <img src="/images/invent-start-menu.png" alt="The Invent start menu with suggested prompts and the message composer" />

    Describe a process you know end to end, including the outcome, systems, judgment calls, and measure of success. Invent works through it with you before building the Agent team.

    You can also choose a task suggested from your project setup, such as creating evals if none exist.
  </Accordion>
  <Accordion title="About you" icon="user">
    <img src="/images/about-you-invent.png" alt="The About You setting in Invent" />

    About You tells Invent who you are so it tailors every response to your role and work from the first message — no re-explaining your context each session. It shapes how Invent talks to you and what it assumes about your work, but it doesn't change Invent's role or hardcode any Tool configuration.

    It adjusts the level of technical detail, makes domain-aware assumptions, and lets Invent address you by name at natural moments.

    To set it up:

    <Steps>
      <Step title="Open Invent settings">
        In the Invent panel, click the three-dot menu, then select **Invent settings**.
      </Step>
      <Step title="Open General">
        Select **General**, enter your details under **About You**, then click **Save**.
      </Step>
    </Steps>
  </Accordion>
  <Accordion title="Model selection and credit usage" icon="brain">
    <img src="/images/invent-model-capabilities.png" alt="The Invent model list showing each model's cost, performance profile, and support for images and files" />

    #### Model selection

    The model dropdown sets which large language model (LLM) powers your Invent session.

    The dollar signs show each model's relative credit cost. Labels such as **Fast**, **Balanced**, **Powerful**, and **Thorough** summarize the trade-off between speed, cost, and capability. The icons beside each model show whether it can work with images and file attachments.

    Your plan determines the default model. You can switch models at any time from the dropdown in the Invent panel.

    #### Credit usage

    The counter beside the model selector shows the credits used in your current session and updates with each interaction.
  </Accordion>
  <Accordion title="Task status and history" icon="list-check">
    <img src="/images/invent-task-statuses.png" alt="Invent task history showing approve, idle, and other statuses" />

    Past sessions in your conversation history show each task with a status: approved (the action was applied), idle (waiting for your input), or completed. You can review what Invent did and track credit spend across sessions from the history view.
  </Accordion>
  <Accordion title="Memories" icon="brain">
    <img src="/images/invent-memories.png" alt="The Memory settings in Invent" />

    Invent automatically learns about you across conversations and stores what it learns as memories. You don't add memories manually — Invent builds them passively as you work.

    Memories let Invent carry context between sessions: your role, the kinds of things you build, naming conventions you prefer, and other patterns it picks up over time.

    To view, search, edit, or delete your memories:

    <Steps>
      <Step title="Open Invent settings">
        In the Invent panel, click the three-dot menu, then select **Invent settings**.
      </Step>
      <Step title="Open Memory">
        Select **Memory**, manage your memory settings, then click **Save**.
      </Step>
    </Steps>

    <Warning>
      Deleting a memory removes it permanently. Invent will re-learn that information if it comes up again in future conversations.
    </Warning>
  </Accordion>
  <Accordion title="Bug reporting" icon="triangle-exclamation">
    When Invent hits a platform issue it can't fix, it logs a bug to the Relevance AI engineering team on your behalf. These reports go directly to engineering rather than support, so you won't receive progress updates.
  </Accordion>
    </AccordionGroup>
  </Tab>
  <Tab title="Manage performance">
    <AccordionGroup>
  <Accordion title="Scheduled check-ins" icon="calendar-clock">
    <img src="/images/invent-scheduled-check-ins.png" alt="A scheduled check-in in Invent" />

    <Note>
      Before setting up a scheduled check-in, add an email or Slack notification channel in [Alerts](/build/invent/invent#alerts) so Invent can notify you about the result.
    </Note>

    #### Schedule a check-in

    Tell Invent what to review and when. It can suggest an interval based on the Agent's activity.

    #### What happens when a check-in runs

    Invent reviews evals, errors, and recent activity. If it finds an issue, it sends a summary and suggested fix. If everything looks healthy, it stays quiet.
  </Accordion>
  <Accordion title="Alerts" icon="envelope">
    <img src="/images/invent-alerts.png" alt="The email and Slack alert settings in Invent" />

    Add at least one email address or Slack channel so Invent can notify you when a scheduled check-in finds something.

    <Steps>
      <Step title="Open Invent settings">
        In the Invent panel, click the three-dot menu, then select **Invent settings**.
      </Step>
      <Step title="Open Alerts">
        Select **Alerts**, add an email address or Slack channel, then click **Save**.
      </Step>
    </Steps>
  </Accordion>
  <Accordion title="Restore a version" icon="clock-rotate-left">
    Ask Invent to roll an asset back to an earlier version — for example, "Restore the previous version of this tool". Invent copies that version into the current draft, leaving the live published version unchanged until you publish. This restores an earlier version of an existing asset; it doesn't recover one that's been deleted.
  </Accordion>
    </AccordionGroup>
  </Tab>
</Tabs>

## Manage Evals with Invent

Invent can build an initial Evals suite, review results, investigate failed Checks, and diagnose performance alarms for Agents and Workforces.

<Card title="Learn more about Evals" icon="chart-line" href="/build/agents/build-your-agent/evals">
  Learn how to create scenarios and reusable Checks, run evaluations, and monitor live performance.
</Card>

<Tabs>
  <Tab title="Create Evals">
    <img src="/images/invent-create-evals.png" alt="Creating evals with Invent" />

    Invent can turn an Agent or Workforce's real usage into a starting Evals suite, including a test set, scenarios, and reusable Checks.

    <Steps>
      <Step title="Start from your Agent or Workforce">
        On the **Run** page, select **Create with Invent** from the testing banner. If a recent Agent task is available, you can instead select **Automate testing** beside it so Invent uses that run as the example.
      </Step>
      <Step title="Describe what success looks like">
        Add any outcomes, edge cases, or requirements that the Evals should cover. A representative task gives Invent useful context about the inputs, expected behavior, and tools involved.
      </Step>
      <Step title="Review and run the Evals">
        Invent creates the Evals setup and runs the test. Open **Evaluate → Runs** to review the score and see which Checks passed or failed.
      </Step>
    </Steps>

    <Tip>
      Start with a task that represents normal production use, then ask Invent to add edge cases once the baseline Evals are working.
    </Tip>
  </Tab>
  <Tab title="Review performance">
    <img src="/images/invent-evals-monitor.png" alt="Reviewing performance results with Invent" />

    Use **Review with Invent** for an on-demand analysis of a completed Evals run or Performance dashboard. Selecting it starts a fresh conversation with the relevant page as context, including the dashboard name when applicable. Invent summarizes the results and recommends improvements, and you can ask it to compare Checks, explain score changes, identify recurring weak points, or prioritize the highest-impact recommendations.

    <Note>
      A review is requested manually; it does not watch performance continuously. Configure an alarm if you want to be notified when a score crosses a threshold.
    </Note>
  </Tab>
  <Tab title="Fix failing Evals">
    <img src="/images/invent-fix-failing-evals.png" alt="Invent proposing fixes for failing evals" />

    Target a specific failed or errored Check when you already know which result needs attention. Invent receives the Check name and run page, investigates why it did not pass, and works with you on a fix.

    <Steps>
      <Step title="Open the failed result">
        Go to **Evaluate → Runs**, open a completed Evals run, then expand a failed test to see its Check results and failure reasons.
      </Step>
      <Step title="Select Fix">
        The **Fix** button appears beside each Check that failed or returned an error. Selecting it starts a new Invent conversation focused on that Check.
      </Step>
      <Step title="Review and verify the fix">
        Invent identifies the likely cause and proposes changes to the Agent, Workforce, or Evals setup. Review the proposed actions before applying them, then rerun the Evals to confirm the Check passes without breaking other behavior.
      </Step>
    </Steps>

    <Tip>
      Use **Review with Invent** for a summary of the entire run; use **Fix** when you want Invent to investigate one failed Check.
    </Tip>
  </Tab>
  <Tab title="Configure an alarm">
    <img src="/images/invent-alarms.png" alt="The alarm configuration in Invent" />

    #### Turn on auto-diagnosis

    Turn on **Auto-diagnosis by Invent** to investigate the first breach and send a diagnosis and proposed fix to the alarm creator's [Invent alert channels](/build/invent/invent#alerts). Invent still shares its findings if the cause is unclear and never applies changes without your approval.

    <Note>
      Alarms are configured in an Agent or Workforce's **Evaluate → Monitor** area, not in Invent settings.
    </Note>

    Alarms evaluate the scores collected by a Performance dashboard and notify you when an overall score or individual Check crosses the condition you set.
  </Tab>
</Tabs>

## MCP vs Invent

Invent and the Relevance AI MCP are often compared, but they solve different problems. Invent builds things _inside_ Relevance AI from natural language. The MCP connects Relevance AI _to the outside world_ — letting external clients call your Tools, and letting your Agents reach into external services.

<CardGroup cols={2}>
  <Card title="Invent" icon="wand-magic-sparkles">
    A forward deployed agent inside Relevance AI. Describe the process you want to run and it builds or edits Agents, Tools, and Workforces for you, landing changes in draft for review.

    Reach for it when you want to build, edit, or debug something inside Relevance AI by describing the outcome.
  </Card>
  <Card title="Relevance AI MCP" icon="plug">
    A bridge to other tools. Call your existing Relevance AI tools from external clients like Cursor or Claude with the [MCP Server](/integrations/mcp/mcp-server), or let your Agents call services like Notion and Linear with the [MCP Client](/integrations/mcp/mcp-client).

    Reach for it when the Tool already exists and you want to run it from Cursor or Claude, or let an Agent call an outside service.
  </Card>
</CardGroup>

<Tip>
  The two are complementary, not competing. Invent uses the same MCP tool surface under the hood — so a common pattern is to build your Agents and Tools with Invent, then call them from Cursor or Claude through the MCP in your day-to-day work.
</Tip>
